# وصل — إدارة WhatsApp والمنصة

تطبيق Flask + SQLite بواجهة عربية RTL. البيانات حقيقية من قاعدة البيانات، وتبدأ فارغة؛ لا حساب مدير أو كلمة مرور افتراضية.

## التشغيل المحلي

```bash
cd /workspace/system-tahcel-aldewon
python -m venv /workspace/.venv
/workspace/.venv/bin/pip install -r requirements.lock
/workspace/.venv/bin/python -m flask --app app create-admin
COOKIE_SECURE=0 /workspace/.venv/bin/python -m flask --app app run --host 0.0.0.0 --port 5000
```

أمر `create-admin` يطلب الاسم والبريد وكلمة المرور بشكل مخفي. طول كلمة المرور الأدنى 12 حرفاً. لا تمرر كلمات المرور في وسيطات الأوامر أو تضعها في Git. `COOKIE_SECURE=0` للتطوير عبر HTTP فقط. الإنتاج يتطلب HTTPS و`COOKIE_SECURE=1` (الافتراضي)، وخادم WSGI مناسب يدعم streaming وworkers متعددة، دون debug. يُحفظ مفتاح جلسة محلي بصلاحيات 0600؛ اضبط `SESSION_SECRET` سراً ثابتاً ومشتركاً عند استخدام أكثر من نسخة.

`/admin` للمالك والدعم؛ `/user` للمستخدم. الدور يُقرأ من قاعدة البيانات في كل طلب. إنشاء المالك حصرياً من الخادم؛ التسجيل العام ينشئ USER فقط. تعليق المستخدم أو تغيير دوره يبطل جلساته فوراً. صفحة Settings للمالك تمنح موظف SUPPORT صلاحية قراءة أو إرسال لكل حساب مفوّض على حدة. لا يتاح لموظف الدعم جدول المستخدمين أو الإدارة العامة.

## ربط WhatsApp Business رسمياً

يلزم تطبيق Meta مع WhatsApp Cloud API، ورقم أعمال مسجل، وصلاحيات `whatsapp_business_messaging` و`whatsapp_business_management` ومراجعة Meta المناسبة عند خدمة شركات أخرى. الربط هنا بواسطة المشغّل، ولا يتضمن Embedded Signup تلقائياً. يجب على المشغّل التحقق من هوية صاحب الحساب وموافقته على ربط هذا الأصل قبل إسناده؛ امتلاك token وحده لا يثبت هوية المستخدم المسجل.

1. اضبط متغير اعتماد مثل `WA_TOKEN` عبر إعدادات الأسرار، مقيّداً بـ`graph.facebook.com`. لا تضع القيمة في المستودع أو دردشة أو سجلات. يمكن لكل حساب استخدام اسم متغير مستقل.
2. اضبط `META_APP_SECRET` و`META_VERIFY_TOKEN` كقيم سرية فعلية في بيئة التشغيل: يستخدمهما التطبيق محلياً للتحقق من HMAC وتحدي webhook، فلا تكفي لهما قيمة placeholder تستبدلها شبكة proxy. `META_GRAPH_VERSION` افتراضياً `v23.0` ويمكن ضبطه وفق إصدار تطبيق Meta.
3. نفّذ مع معرّفات حقيقية:

```bash
/workspace/.venv/bin/python -m flask --app app link-business \
  --owner USER_ID --phone-id META_PHONE_NUMBER_ID \
  --waba-id META_WABA_ID --token-key WA_TOKEN
```

يتحقق الأمر من الرقم عبر Graph API وعضويته في WABA قبل الحفظ. لا يُحفظ رمز الوصول في قاعدة البيانات، بل اسم المتغير فقط. لا تتيح API عامة إسناد رقم أعمال يدّعيه المستخدم.

4. يدخل المالك العادي إلى حسابه، ثم حسابات واتساب ← تفاصيل ← منح التفويض. الموافقة منفصلة عن التسجيل، مسجلة بتاريخ وإصدار، وقابلة للسحب فوراً. مدير المنصة لا يستطيع منح الموافقة نيابة عنه.
5. اضبط webhook في Meta على عنوان HTTPS عام ينتهي بـ`/webhook` واشترك في حقل `messages` لحساب WABA. يدعم التحقق من التحدي وHMAC SHA-256، ومطابقة كل من WABA ومعرف الرقم، وإزالة التكرار باستخدام معرف رسالة Meta.
6. يستقبل التطبيق رسائل النص وحالات التسليم. الملفات والصور والقوالب ليست مدعومة حالياً. الرد النصي متاح فقط خلال 24 ساعة من آخر رسالة واردة ومن الحساب المرتبط بالمحادثة. خطأ الإرسال لا يُسجّل على أنه نجاح. عند انتهاء المهلة قد يكون Meta قد استلم الرسالة: تحقق من حالتها قبل إعادة المحاولة.

التحديث الحي عبر Server-Sent Events يعيد التحقق من صلاحيات المستخدم والتفويض كل ثانيتين، ويحدّث الواجهة من API المحمية. لا يرسل stream محتوى رسائل. يجب تعطيل buffering في reverse proxy ودعم اتصالات streaming. الحساب الشخصي `wa.me` فقط، ولا يُسمح بقراءة محادثاته من أي دور.

## الوظائف والحدود

- بحث المستخدمين وتفاصيلهم، التعليق والتفعيل، الأدوار، حدود المحادثات، وطلب الحذف.
- فهرس الحسابات، صندوق محادثات عالمي مفوّض مع صاحب الحساب ورقمه، فلاتر المستخدم والرقم والتاريخ، والرد.
- إحصائيات من DB، رسوم يومية وشهرية، وسجل مشاهدات/إرسال/تعديلات إدارية.
- إدارة خطط Free/Pro/Business وحالة الاشتراك داخلياً. لا توجد بوابة دفع أو فوترة تلقائية؛ حد المحادثات يضبطه المدير مستقلاً.
- حدود المحادثات تمنع إنشاء محادثات إضافية من webhook عند بلوغ السقف؛ الرسائل لمحادثات جديدة فوق الحد لا تُستورد، ولا تُحذف المحادثات القائمة عند تخفيضه.
- الحذف يوقف الحساب ويسحب التفويض فوراً. لتطبيق الاحتفاظ شغّل يومياً بمجدول خارجي:

```bash
/workspace/.venv/bin/python -m flask --app app purge-deleted
```

بعد 30 يوماً يمسح الأمر الرسائل والحسابات والتفويضات والاشتراك ويخفي بيانات هوية المستخدم؛ يُبقي معرّفاً مستعاراً وسجل تدقيق محدوداً. لا يمسح نسخة احتياطية خارجية تلقائياً. قرر سياسة حفظ سجلات التدقيق والنسخ الاحتياطية قبل الإنتاج.

ملفات SQLite ومفتاح الجلسات في `instance/` خارج Git. احتفظ بنسخ آمنة مع صلاحيات مناسبة. SQLite مناسب للبدء على نسخة واحدة؛ يلزم تقييم PostgreSQL، pagination، طابور إرسال دائم ومعالجة أحجام البيانات الكبيرة قبل التشغيل واسع النطاق. لا تُعد هذه النسخة مراجعة أمان إنتاجية مستقلة.
